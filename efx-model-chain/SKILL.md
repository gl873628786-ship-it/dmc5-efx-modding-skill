## I — 方法论骨架 (Interpretation)

模型/网格在 EFX 里有一个反直觉的核心事实：**同一份几何数据，在不同段里被赋予完全不同的语义。**

**语义一：在 `TypeMesh` 里，子网格数 = 帧数**
- 静态网格 → `FrameCount` 填 **1**。
- 顶点动画 → `FrameCount` 等于**模型的子网格数量**（示例：18 个子网格 → 填 18）。
- 关键推论：**把一个多子网格的模型塞进去，它不会保持静态**——引擎会自动把它**当作逐帧顶点动画**。所以"我只要一个静态模型"却给了 30 个子网格，必须把 `FrameCount` 从 1 改成 30，否则帧数不对。
- 子网格数比原来多或少**都可以**，只要**命名正确**（导入 FBX 时的网格命名）。

**语义二：在 `MeshEmitter` 里，网格顶点分布 = 粒子分布**
- 采样逻辑是"每个顶点撒若干粒子"，所以粒子密度**正比于顶点密度**。
- 顶点疏密不均 → 粒子在密集处扎堆、稀疏处空白，呈现"糊成一团 + 大片空洞"。
- 这类问题的根因在**源网格拓扑**，不在 efx 参数——调 EFX 里的数量/散布参数都改不匀。
- 且 `MeshEmitter` **只支持 `TypeGpuBillboard`**，换别的渲染类型不生效。

**材质不在这里改**
`TypeMesh` 换完模型后，**贴图仍是原来的**——因为材质只用 mdf 的**第一个材质**（材质名对不上不用管）。要改外观，必须去 `mdf` 文件里找到贴图引用并修改。

**导出纪律**
用 3DS Max 导出替换用 FBX 时：**只选模型，别选到父级**；摆好位置后直接改名导出。

一句话概括：**先确定"这份几何数据在当前段里代表什么"，再决定怎么用它、改哪个计数字段。**

## A1 — 源素材中的应用 (Past Application)

### 案例 1：静态网格替换（齿轮）

- **问题**：想把某个特效的网格换成自制的齿轮模型。
- **方法的使用**：3DS Max 导入齿轮 → 摆好位置 → 改名导出 FBX（**只选模型、不选父级**）→ 回到 010 Editor 用模板替换 `TypeMesh` 的模型路径 → `FrameCount` 填 1。
- **结论**：静态网格填 1；材质名对不上不用担心。
- **结果**：提示"成功替换"，进游戏看到替换后的静态网格。

### 案例 2：顶点动画替换（18 子网格 vs 原 16）

- **问题**：用一个 18 子网格的模型替换原蝴蝶（16 子网格）。
- **方法的使用**：确认"多两个也可以，只要命名正确"，并把 efx 里的**个数改为 18 与子网格数量对应**。
- **结论**：进游戏后模型换了，但**贴图仍是蝴蝶的**——需另去 mdf 里改贴图引用。
- **结果**：模型替换成功；确立了"换模型 ≠ 换外观"这条认知。

### 案例 3：MeshEmitter 的顶点分布实验

- **问题**：想让粒子按某个形状分布。
- **方法的使用**：用 `MeshEmitter`（配 GpuBillboard），在 3DS Max 里制作**两种不同的顶点分布方式**做对比。
- **结论**：**顶点分布状况直接决定粒子分布状况**。
- **结果**：进游戏对比确认；同时验证亮度需 ≥ 500 才能看见。

## E — 可执行步骤 (Execution)

1. **先判定段与语义**：
   - 是挂模型播放 → `TypeMesh`；是按顶点撒粒子 → `MeshEmitter`（确认渲染类型是 `TypeGpuBillboard`）。
   - 完成标准：写明用的是哪个段、这份几何数据代表"帧"还是"发射点"。

2. **TypeMesh：数子网格，定 FrameCount**：
   - 静态网格 → `FrameCount = 1`。
   - 有多个子网格 → 引擎视为顶点动画，`FrameCount` = 子网格数（多/少都可以，命名要正确）。
   - 完成标准：写出子网格数 N，并把 FrameCount 填成对应值。
   - 判停条件：若"我只要静态模型"但模型确实多子网格 → 明确告知会变成逐帧动画，需自行取舍（拆网格 or 接受动画语义）。

3. **MeshEmitter：检查顶点分布**：
   - 在 3DS Max 里看该模型的**布线疏密**。
   - 完成标准：若顶点疏密不均 → 判定为"源网格拓扑问题"，**不要靠调 efx 参数解决**，回到建模改均匀布线。

4. **导出与替换**：
   - 3DS Max 导出：**只选模型、不选父级**，摆好位置、命名正确、改名导出 FBX。
   - 回 010 Editor 用模板替换 `TypeMesh` 的模型路径。
   - 完成标准：提示替换成功；F5 无 `*ERROR`。

5. **单独处理外观（材质/贴图）**：
   - 进 `mdf` 文件找到贴图引用并修改（材质名不重要，只用第一个材质）。
   - 完成标准：进游戏外观与模型一致。
   - 判停条件：若只换了模型没动 mdf → 预期结果是"模型换了、贴图还是旧的"，属正常现象，不是失败。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要换的是**贴图/序列帧**而不是几何 → 用 `efx-texture-chain`。
- 还没决定用哪个渲染类型 → 用 `efx-render-type-selection`。
- 编辑器报 `*ERROR` 或游戏已崩 → 先用 `efx-crash-troubleshoot`。

### 源素材中警告的失败模式

- **多子网格被当成逐帧动画**：以为塞进去就是静态网格，结果它在"播动画"，帧数还不对。
- **MeshEmitter 顶点分布不均** → 粒子扎堆 + 大片空洞；改 EFX 参数无效，因为根因在源网格。
- **MeshEmitter 配了非 GpuBillboard 的类型** → 不生效。
- **换完模型以为外观也换了** → 材质只用 mdf 第一个材质，必须另去 mdf 改贴图。
- **导出时连父级一起选** → 导出内容不正确。
- **子网格命名不规范** → 虽允许多/少，但"命名正确"是硬前提，命名错会失败。

### 作者的盲点 / 局限

- 作者**没有解释**"为什么多子网格会被识别为顶点动画"——这是观察结论，机制未证实。
- "命名正确"的具体规则（大小写？前缀？）作者未展开。
- 只演示了 3DS Max + FBX 这一条导出链路；其它 DCC 工具**无素材证据**。
- 顶点分布影响粒子分布是作者的演示结论，未给定量关系。

### 容易混淆的邻近方法

- **"模型链" vs "贴图链"**：都叫"换资源"，但一条走 TypeMesh/mdf/fbx，一条走 UVSequence/uvs/tex。
- **FrameCount（子网格→帧） vs 序列帧网格数（8×8→UV 坐标）**：两者都是"个数必须匹配"，但一个是几何的，一个是贴图的。
- **"模型没换成功" vs "模型换了但贴图没换"**：后者是预期行为，去 mdf 即可；前者才需要排查命名/导出。
