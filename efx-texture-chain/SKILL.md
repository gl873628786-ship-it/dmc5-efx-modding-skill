## I — 方法论骨架 (Interpretation)

贴图**不是一个文件，是一条链**：

```
efx  ──(UVSequence 段里的路径)──▶  uvs 文件  ──(内部的 tex 路径)──▶  tex 贴图  ──▶  .dds 图
```

改皮肤时最常见的错误是"只改了一处"——换了图文件却不动 efx，或改了 efx 却不动 uvs 里的 tex 路径。所以固定动作是**先画链路图，再逐跳替换，每跳都查 size**。

**跳 1：efx → uvs**
UVSequence 段里存着 uvs 文件的路径。改它要分两种情况：
- **路径变短** → 可以直接改，长度字段不动也不会错位，**无需同步**。实用技巧：把路径"短化"到以 `vfx`（视频 OCR 误作 `vtx`）文件夹开头、保留 `-uvs` 后缀，这样 uvs 就能放进 MOD 自己的 `x64` 文件夹里随包分发，不再依赖本机绝对路径。（注意：不能放 `natives`。）
- **路径变长** → 必须先改 `pathsize` 计数，再**按每 +1 字符插 2 字节**补足空间（示例：53→55，加了 2，所以插 4 字节），最后 F5 重解析。顺序反了就会错位。

**跳 2：uvs 位置**
把 uvs 文件放到 efx 里写的那条路径上。作者的建议：**让 uvs 与 tex 相对位置保持对应，方便修改与纠错。**

**跳 3：uvs → tex**
uvs 文件内容基本只有**一个 tex 文件的路径**，改法与跳 1 相同。这一跳最容易被忘："我图都换了怎么没变"通常就卡在这里。

**跳 4：tex 元数据（彩色贴图专属）**
把**黑白**贴图换成**彩色**贴图时，只换图不够——必须去 tex 文件（`tex_light` 相关字段）里改对应值，否则引擎仍按旧的采样/光照参数解释新图，表现为"能显示但颜色/亮度不对"。

**序列帧的额外约束：网格数匹配**
替换序列帧动画（如烟雾换火焰）时，新素材的**网格划分数必须与原图一致**。因为 `uvs` 存的不是"帧索引"而是**每一帧的 UV 坐标表**——坐标是按原始网格切分算好的。换成 8×4 会与按 8×8 算好的坐标对不上，帧帧错位。爆炸/火焰/烟雾类特效多为 8×8，可互相替换。**结论：优先选"结构相同、内容不同"的素材，而不是"内容最好、结构不同"的素材**，避免结构性返工。

## A1 — 源素材中的应用 (Past Application)

### 案例 1：缩短路径 + 保留 -uvs 后缀，让 uvs 能随 MOD 打包

- **问题**：uvs 用了本机绝对路径，无法随 MOD 分发。
- **方法的使用**：把路径缩短到以 `vfx` 文件夹开头、保留 `-uvs` 后缀，从而能放进 MOD 自己的 `x64` 文件夹（不放 natives）。
- **结论**：短化路径**不需要**动 pathsize。
- **结果**：uvs 可随包分发，摆脱绝对路径依赖。

### 案例 2：加长路径的固定顺序

- **问题**：需要把 uvs 路径从 53 字符加长到 55 字符。
- **方法的使用**：① 先把 `pathsize` 改成 55；② 在 uvs path[52] 之后用插入字节（Ctrl+Shift+L）插入 2×2 = 4 个字节；③ 按 F5 刷新变量。
- **结论**：先是"声明"，再是"实体"，最后校验——顺序不可颠倒。
- **结果**：路径与长度重新对齐，模板解析恢复正常。

### 案例 3：彩色贴图不生效，卡在 tex_light

- **问题**：把贴图换成彩色版，进游戏发现不对。
- **方法的使用**：去 tex 文件的 `tex_light` 中搜索并改对应值。
- **结论**：彩色与黑白贴图所需的元数据不同，只换图不改元数据就无效。
- **结果**：改完 tex_light 后彩色贴图正确显示；同时观察到 TypePolygon 的纹理是半透明的。

### 案例 4：8×8 烟雾换成 8×8 火焰

- **问题**：想把某特效的烟雾动画换成火焰。
- **方法的使用**：专门选用同样 8×8 的火焰序列帧。
- **结论**：网格数必须匹配，否则要手工重算 uvs 里全部帧坐标，成本极高。
- **结果**：替换成功，进游戏动画正常播放。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 想给特效**换一张贴图/皮肤**（"把这个火的颜色换成蓝色""换成我做的图"）。
2. 换了图**进游戏没变化**或显示异常（"图都换了怎么还是原来的"）。
3. 需要**改资源路径**，不确定改长度会不会崩、要不要同步 size。
4. 想把资源**打包进 MOD 分发**，摆脱本机绝对路径。
5. 要**替换序列帧动画**（烟雾/火焰/爆炸 flipbook），不确定网格数怎么处理。
6. 换的是**彩色贴图**而不是黑白图，结果颜色/亮度不对。

### 语言信号（用户的话里出现这些就应激活）

- 中文：「换贴图」「换皮肤」「换序列帧」「换了没生效」「uvs 路径」「pathsize」「路径变长」「打包 MOD 路径」「8×8」「tex_light」「彩色贴图不显示」「dds 换掉」
- English: "replace the texture", "change the uvs path", "pathsize", "why didn't my new texture show", "swap the flipbook animation", "pack the mod path", "8x8 sequence", "tex_light", "color texture not working"

### 与相邻能力的区分

- 与 `efx-model-chain` 的区别：本能力管**贴图/UV 链**（efx→UVSequence→uvs→tex）；那个管**几何/网格链**（TypeMesh + mdf + fbx、MeshEmitter 顶点）。换"皮"找本能力，换"骨"找那个。
  ⚠️ **最容易混淆的一点**（压力测试暴露）：当用户说"我把**模型**换掉了，可**贴图**还是旧的那个，要去哪改"时，**不要落到本能力**——模型替换后的材质/贴图归属由 **mdf** 决定，是模型链路的收尾步骤，应交给 `efx-model-chain`。本能力只在"没有换过模型、单纯要替换贴图或序列帧"时接管。
- 与 `efx-safe-structure-edit` 的区别：本能力只处理**路径字段的长度同步**（pathsize）；增删整个 Segment/Effect 的计数同步找那个。
- 与 `efx-render-type-selection` 的区别：本能力不动渲染类型；若问题是"某个轴缩放没反应"这类类型边界，找那个。
- 与 `efx-crash-troubleshoot` 的区别：本能力负责在链路改造中**避免**制造故障；已经崩了、需要先分流故障类型时找那个。

## E — 可执行步骤 (Execution)

1. **画出链路图，确定这次要动哪几跳**：
   - `efx →(UVSequence 路径)→ uvs →(uvs 内 tex 路径)→ tex → dds`
   - 完成标准：能列出"本次要改的跳"清单（常见是 3 跳：efx 路径、uvs 位置、uvs 内路径）。

2. **改路径，先判变长还是变短**：
   - 变短 → 直接改，pathsize 不动。
   - 变长 → **先改 pathsize → 再插 2 × 新增字符数字节 → F5 重解析**。
   - 完成标准：F5 后模板无 `*ERROR`，变量树长度与字符串一致。
   - 判停条件：若不确定新增了几个字符，**先数清再动手**；插字节数必须是"字符数 × 2"。

3. **逐跳落地文件位置**：
   - 把 uvs 放到 efx 里写的路径上；把 tex 放到 uvs 里写的路径上。
   - 建议 uvs 与 tex 相对位置对应，便于纠错。
   - 完成标准：三处路径彼此自洽（efx 写的 = uvs 实际所在；uvs 写的 = tex 实际所在）。

4. **按素材类型做额外处理**：
   - **彩色贴图** → 去 tex 的 `tex_light` 改值。
   - **序列帧动画** → 确认新素材网格数与原图一致（常见 8×8）；不一致则要么改用同网格素材（推荐），要么连 uvs 一起换成按新网格算的版本。
   - 完成标准：写明"是否需要改 tex_light / 网格数是否匹配"。

5. **F5 → 进游戏验证（改一处看一次）**。
   - 完成标准：新贴图/动画正确显示，无崩溃。
   - 判停条件：若开游戏时换的是序列帧动画、重进关卡不刷新 → 退到主界面重新选关再进（缓存例外，见 `efx-crash-troubleshoot`）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要改的是**模型/网格**而不是贴图 → 用 `efx-model-chain`。
- 要**增删** Segment/Effect 结构（不是改路径） → 用 `efx-safe-structure-edit`。
- 编辑器里已经报 `*ERROR` 或游戏已崩 → 先用 `efx-crash-troubleshoot` 分流。

### 源素材中警告的失败模式

- **只改一处**：换了图却不改 uvs 里的 tex 路径，或改了 efx 却不动 uvs 位置 → 全链失效。
- **加长路径时忘了先改 pathsize**，或插入字节数写成"新增字符数"而不是 ×2 → 路径字段与后续数据错位。
- **插完字节忘了 F5** → 变量树还是旧偏移，后续操作全错。
- **换彩色贴图不改 tex_light** → 贴图显示但颜色/亮度明显不对。
- **用不同网格数换序列帧**（8×8 → 8×4）→ 因为 uvs 存的是逐帧 UV 坐标而非帧索引，采样位置全部错位、逐帧画面串帧。
- **把 uvs 放进 natives** → 随 MOD 卸载一起消失（见 `efx-edit-hygiene`）。

### 作者的盲点 / 局限

- 作者说"uvs 文件的内容**貌似**只有一个 tex 文件的路径"——"貌似"说明他未穷尽 uvs 的字段；本能力据此只主张"这一跳改法如此"，不主张 uvs 只有这一个字段。
- 只演示了 DDS/TEX 这一套；其它贴图格式无素材证据。
- 彩色贴图需要改 tex_light 是经验结论，作者未说明具体是哪些值、为什么。

### 容易混淆的邻近方法

- **贴图链 vs 模型链**：都叫"换资源"，但走的是两条完全不同的引用链。
- **"uvs 存坐标" vs "uvs 存帧号"**：前者才是真相，这正是网格数必须匹配的根因。
- **pathsize（每字符 2 字节） vs Condition Block size（按字节直接计）**：两者都叫 size，但换算规则不同。
