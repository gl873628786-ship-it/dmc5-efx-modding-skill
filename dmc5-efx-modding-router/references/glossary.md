# GLOSSARY — 鬼泣5 EFX 特效编辑术语词典

> 本词典是全部能力的共享词典。`与常识的差异` 一栏是本词典最有价值的部分：
> 这些术语若按字典义或直觉理解，下游会做出完全错误的操作。
> 来源标注：`【原】` = thezippotm 原教程；`【OCR pNN】` = 视频第 NN 分 P 画面文字。

---

## A. 文件与结构层

| 术语 | 来源中的定义 | 与常识的差异 |
|---|---|---|
| **EFX 文件** | 【原】"EFX 文件 → EFX Header → Name Buffer → Linked/Embedded EFX → Effect[]（Segment[]）"；【OCR p02】"用 010 编辑器打开 efx 文件" | ≠ 特效资源（贴图/模型）。EFX 只是特效的**结构描述/清单**，皮与骨全部外链。≠ "一个文件 = 一个特效"，单文件可含多个 Effect（示例含 18 个）。 |
| **EFX Header** | 【原】"头部：Effect Count、Linked EFX Count…"；【OCR p02】"数字 18 表示这个 efx 文件里有 18 个特效组" | ≠ 固定魔数/版本号头，它是**一组可手工编辑的计数元数据**。且**并非所有计数都在这里**——Segment Count 在 Effect 内、Override Hash Count 在 TypeMesh 段、条件块的 size 在 Condition Blocks 里。 |
| **Effect / 特效组** | 【原】"顶层元素，一个文件可含多个特效"。视频里一律叫"特效组" | ≈"一个特效"，但它是**容器**，内部还有若干 Segment。≠ 单个粒子、≠ 单张贴图。 |
| **Segment / Attribute / Property** | 【原】"每个特效内部的组成单元，**同一层级的不同叫法**" | ≠ 属性值（不是"颜色=红"这类键值对），而是**一段带类型 Id 的二进制结构**。三者是**同义词**，不是三层嵌套。 |
| **Id / Item Type ID** | 【原】"决定排序与优先级，**Id 越大优先级越高，冲突时覆盖 Id 较小的**"；"ScaleAnim = 2Ah、Life = 2Ch" | ≠ 序号/数组下标。它是**类型码**：2Eh 永远是 UVSequence、2Ch 永远是 Life。冲突规则是"**Id 大者覆盖小者**"，非"后写覆盖先写"。⚠ 该规则仅一个场景被演示过。 |
| **Name Buffer** | 【原】"名称缓冲区，粘贴链接/嵌入 EFX 的位置" | ≠ 名字显示区。它是**结构上的固定插入点**——Linked/Embedded EFX 必须粘在它之后。 |
| **Linked EFX / Embedded EFX** | 【原】"（推荐用 Linked）"；"若选 Embedded 型，还需把 Path/EFX size 值按新增字节数同步增加" | 两者都是"引用另一个 efx"，差别在**存储方式**：Linked 外链（改体积不用碰 size）；Embedded 内嵌（每次改体积都要同步 size）。≠ 超链接、≠ 继承关系。 |
| **Override Hash / Override Hash Count** | 【原】"值/贴图覆盖的数量（TypeMesh 专属）"；"覆盖贴图时必须匹配 mdf 中的哈希值；覆盖值还必须匹配哈希值和参数数量" | ≠ 校验用的校验和。它是**用哈希定位要覆盖的 mdf 贴图或值的寻址键**。只改名字不行，哈希必须完全一致。 |
| **Condition Block（条件块）** | 【OCR p09】"ukn 设定为 0 时则只在某些特定条件下触发"；"ConditionBlocks 里就是限制条件的种类"；"3 代表有 3 种限制条件，108 代表占了 108 个字节" | ≠ 脚本 if 条件。它是**文件里的条件索引表**：条件种类数 + 每条件对应的特效索引。新增必须**粘末尾**，插中间会让索引整体平移。 |
| **变量树（Variable / Template Result）** | 【OCR p02】"找到 efx 模板运行，就可以看到下面的模板变量" | ≠ 程序运行时变量。它是 010 Editor 模板解析二进制后的**字段视图**。字段名是**社区反推**的，可能不准（大量 ukn）；"字段名 = 引擎语义"只是假设。 |
| **模板 .bt** | 【OCR p01】"下载特效模板文件 EFX.bt"；【OCR p02】"执行模板 D:\010Editor v11.0.1\DMC5template\DMC5_EFX\DMC5_EFX.bt" | ≠ 游戏自带解析器。是**社区反推的 010 Editor 二进制模板脚本**，只负责把二进制翻译成变量树。**不同文件类型要用不同模板**（efx → `DMC5_EFX.bt`、uvs → `RE_UVS.bt`、场景 → `RE_RSZ_*.bt`），混用即解析失败。 |
| **natives 文件夹 / pak / patch pak** | 【OCR p01】"使用管理器安装 MOD 之后会在鬼泣5根目录生成 natives 文件夹"；"一卸载 MOD，根目录的 natives 文件夹就会消失"；【OCR p09】"re_chunk_000.pak.patch_005/natives/x64/scene/players/pl0800.scn" | natives ≠ 游戏原始资源目录，而是 **MOD 管理器挂载的覆盖层**（游戏实时读取，开着游戏改也能生效），其生命周期绑定 MOD 安装状态。pak / patch pak ≠ 普通压缩包，是 RE Engine 资源容器，`.pak.patch_NNN` 按序号叠加。 |
| **RE Engine** | 【原】（教程唯一平台）；示例为 `pl0800`（玩家维吉尔） | ≠ 跨作通用规范。DMC5 与 RE2/RE3/RE4/MHR 虽同属 RE Engine，**efx 属性表互不相同**，照搬会全错。 |

## B. 资源与链路层

| 术语 | 来源中的定义 | 与常识的差异 |
|---|---|---|
| **UVSequence（Id 2Eh）** | 【原】"**所有基于贴图的特效都必需此段**。它链接一个 uvs 文件，uvs 文件再链接贴图（单图或 flipbook）。可调动画速度、动画类型、起始帧。" | ≠ 贴图本身。它是贴图/序列帧的**开关与调度段**，本身不含图像。它是"面片类/网格类能不能显出皮"的**先决条件**。 |
| **uvs 文件** | 【OCR p03】"uvs 文件的内容貌似只有一个 tex 文件的路径"；【OCR p15】"**动画每一帧的坐标信息都在 UVS 文件里面**" | ≠ 贴图。uvs 存的是**每一帧的 UV 坐标映射表**（外加一条指向 tex 的路径）。换序列帧时**网格数必须匹配**（8×8 换 8×8），否则坐标对不上。 |
| **tex 文件（tex_light / tex_smoke）** | 【OCR p03】"可以用 noesis 打开 tex 文件看看贴图的样子"；"如果你改的是这种彩色的…需要修改一些值来使其生效，在 tex_light 中搜索" | ≠ 通用 DDS/PNG。tex 是 RE Engine 贴图文件（用 Noesis 查看）。关键差异：**彩色贴图（非纯黑白图案）需要在对应资源文件夹里改某些值才生效**。 |
| **mdf / mdf 哈希** | 【原】"Type Mesh 配合 mdf（材质/贴图分配文件）生成静态网格。**材质名被忽略**，mdf 中的第一个材质会应用到模型的所有子网格。" | ≠ 贴图。mdf 是**材质/贴图分配文件**。≠ 按名字匹配：覆盖靠**哈希**定位，材质名会被忽略。 |
| **fbx** | 【OCR p11/p12】"导出 fbx 网格/动作"；"Group 后面的数字顺序"；"后面为材质名"；"摆放好位置之后，改名即可导出" | ≠ 模型交付的最终格式。fbx 是 3DS Max ↔ RE Engine 之间的**中转格式**，且**命名有约定**（Group 后的数字顺序、材质名后缀影响子网格/帧的识别）。 |
| **Noesis / 3DS Max / EMV 引擎** | 【OCR p01】"可能会用到的软件：PS、3DS MAX、Noesis"；"最好还要有一个类似 EMV 引擎或者无人机工具的东西，能随意拉镜头来观察效果" | Noesis ≠ 建模软件，是**资源查看/转换**工具（看 tex、预览/转换 fbx）。3DS Max 在本教程里主要用来做**替换模型的摆位+改名+导出**。EMV/无人机 ≠ 游戏本体，是**自由拉镜头预览**的辅助。三者都不是编辑主工具——主工具是 010 Editor。 |
| **序列帧动画 / flipbook** | 【OCR p15】"单个纹理特效或者序列帧动画"；"这个烟雾是 8×8 的" | ≠ 视频 / GIF / 时间轴动画。它是**一张图集按 UV 坐标逐帧播放**。帧的坐标**不在贴图里**，在 uvs 文件里。 |
| **FrameCount / 子网格** | 【OCR p11】"FrameCount 动画帧数量…静态网格填 1，顶点动画看网格数"；【原】"若网格有多个子网格，会被当作逐帧动画（每个子网格是一帧）" | ≠ 时间轴帧数。这里 FrameCount = **子网格数**，每个子网格 = 顶点动画的一帧；静态网格填 1。子网格数**可多可少**（"注意命名正确即可"），但 FrameCount 必须与实际对应。 |

## C. 数值与语义层

| 术语 | 来源中的定义 | 与常识的差异 |
|---|---|---|
| **Min / Max** | 【OCR p05】"但凡看见 Min 和 Max 这种情况，那就是在 Min 值和 Max 值间取随机"；【OCR p06】"**Max 的值必须比 Min 大 1 以上，否则游戏崩溃（都是 0 的情况除外）**" | ≠ 上下限钳制（clamp）。它是**区间随机**。硬约束是 **Max − Min ≥ 1**，违反即**崩溃**（全 0 除外）——这不是逻辑限制，而是崩溃条件。 |
| **Range** | 【原】"若 ScaleX = 10、ScaleXRange = 2，则每次触发时 X 轴缩放取 8~12 的随机值"；【OCR p05】"实际上速度就是在 0.7 与 1.3 之间取随机" | ≠ Min/Max 区间。Range 是**基准值 ± 浮动范围**的对称随机。`XxxRange` 与 `XxxMin/Max` 是**两套独立机制**，同一属性里可能并存——本领域最高频的混淆点。 |
| **StartFrame / Starting Frame** | 【原】"起始帧的 Min 必须至少比 Max 低 1，否则游戏会崩溃（原因未知）。**同时适用于 TypeMesh 和 UV Sequence**。" | ≠ "从第 0 帧开始"的固定起点。它是**从第几帧开始**的随机区间，因此同样受 Min/Max 差值 ≥1 的崩溃约束；且与"总帧数（FrameCount）"不是一回事。 |
| **Duration / FadeInDuration / FadeOutDuration** | 【OCR p06】"淡入时间 FadeInDuration / 维持时间 Duration / 淡出时间 FadeOutDuration / 未知效果：此值设定为 1 效果将一直存在"；【原】"触发条件绑定于 Life 属性里的 Duration 值，**FadeOutDuration 被忽略**" | ≠ 三个时长地位对等。**Duration 才是消亡触发的时间基准**，FadeOutDuration 被忽略。且某"未知效果"字段设为 1 = **效果一直存在**。 |
| **弧度 vs 角度** | 【OCR p07】"让效果转 90 度就填入 1.57079…建议精确到小数点后五位"；"位置和旋转可填负值，缩放不行" | ≠ 界面常见的"度"。**所有旋转一律是弧度**（90° = 1.57079）。且**位置/旋转可负、缩放不可负**。 |
| **Spawn / Spawn Cycle（Id 01）** | 【原】"控制生成循环（Spawn Cycles）。**设为 0 表示无限生成循环**"；【OCR p08】"循环周期填 0 就表示一直都会出现"；"填 60 即为延迟一秒" | ≠ 一个"生成数量"。这**一段同时管**个数/组数/间隔/循环周期/延迟。反直觉：**循环周期填 0 = 一直出现**（不是"不生成"）；延迟单位疑似**帧**（60 ≈ 1 秒）。 |
| **Parent Options / Follow Bone（Id 0B）** | 【OCR p10】"这里的**十个数值全都是填 0 或 1**，0 即为不跟随，1 即为跟随"；"特效触发后是否继续跟随父级（骨骼）→ FollowBone"；【原】"建议不要改 Position 值（**设为 0 会默认到关卡世界原点**）" | ≠ 父子层级设置。它是**一组成员跟随开关**（10 个 0/1）。Follow Bone ≠ 绑定骨骼，而是**生成后是否继续跟随**。Position 的 0 语义与 Rotation/Scale **不对称**（是"跟到原点"）。 |
| **nits** | 【OCR p21】"这个属性里的亮度单位**可能**是 nits，太低了没效果，建议干到 500 以上看看" | ≠ 0~1 的亮度百分比（按百分比填 = 完全没效果）。作者**推测**是 nits（cd/m²），量级数百以上——注意原话是"可能是"，属作者自认未证实的单位。 |
| **ukn（不明的值）** | 【原】大量 ukn 字段；【OCR p19】"这下面的 12 个值我测了好久，发现好像只有编号【0】有影响" | ≠ 隐藏功能，≠ 可随意填写的占位。它是**作者明确承认"语义未知"的字段**。部分已被试出语义（PtLife ukn3 / PtColliderAction ukn2），其余仍是猜测。**未知 ≠ 无作用**。 |

## D. 渲染类型

| 术语 | 来源中的定义 | 与常识的差异 |
|---|---|---|
| **TypeBillboard3D（0Fh）** | 【原】"最常用的特效类型之一。贴图**始终朝向摄像机**，因此**只能绕一个轴旋转**。" | 与 Polygon 的唯一实质差别就是"朝不朝摄像机"，而这一条直接决定了旋转自由度。 |
| **TypeBillboard2D（0Dh）** | 【原】属性表中列出 | ≠ 3D 的"低配版"。2D 用于屏幕/2D 空间语义，坐标系不同；教程**未展开讲解**，不要按 3D 的直觉套用。 |
| **TypePolygon（1Dh）** | 【原】"与 TypeBillboard3D 唯一区别是**不朝向摄像机**"；【OCR p17】"可以三个轴旋转…旋转依旧是填弧度值" | 它不是"更高级的 Billboard"，而是"放弃了朝向约束、换来了三轴旋转自由度"的类型。 |
| **TypeMesh（11h）** | 【原】"配合 mdf 生成静态网格。材质名被忽略，mdf 中的第一个材质会应用到所有子网格。若网格有多个子网格，会被当作逐帧动画。" | 一身兼两职：**静态网格**（FrameCount=1）与**顶点动画**（FrameCount=子网格数）。反常识：材质名被忽略；"多子网格"被自动解释为"逐帧"，而不是"多部件"。 |
| **TypeGpuBillboard（69h）** | 【原】"用于生成**大量粒子**。每个粒子朝向摄像机。**缺点：即使配合 ScaleAnim 也无法在 X、Y 轴单独缩放**。"；【OCR p21】"太低了没效果，建议干到 500 以上" | ≠ Billboard3D 的批量版。它带硬限制（**不支持逐轴缩放**），亮度单位疑似 nits（需 ≥500）。属"性能换自由度"的典型。 |
| **MeshEmitter（5Fh）** | 【原】"按网格形状生成粒子特效。**目前仅支持 TypeGpuBillboard**。生成位置基于网格顶点，需均匀分布顶点以免粒子聚集。" | ≠ 普通发射器，粒子分布**完全由网格顶点决定**。顶点不均就聚成一坨，且**在 efx 里调参无法修正**。 |
| **TypeRibbon\* 族 / TypeNoDraw** | 【原】属性表：TypeRibbonFollow / Length / Chain / FixEnd / Lightweight / Trail（各带 Expression 变体）；TypeNoDraw（22h） | TypeRibbon ≠ 一种类型，而是**一族**，行为各不相同。TypeNoDraw ≠ 隐藏或透明，它是"**不绘制本体**"的类型。**两者教程均未展开**，不可凭空外推。 |
| **Distortion（3Ch）** | 【原】"把基于贴图的特效**转为扭曲特效**。**并非所有贴图特效都适用**。" | ≠ 屏幕后处理滤镜。它作用于某个贴图特效本身，且有适用范围限制。近邻 ProceduralDistortion（77h/78h）是程序化版本，二者不可混。 |

## 最容易混的五对（速查）

1. **Min/Max vs Range** —— 后缀决定机制：两端点 vs 基准±浮动。
2. **uvs vs tex** —— 坐标表 vs 图。
3. **Segment vs 属性值** —— 一段二进制结构 vs 一个键值对。
4. **Id vs 序号** —— 类型码 vs 出现顺序。
5. **Effect Count vs Segment Count** —— 文件级 vs Effect 局部（报错行号量级是判别线索：四位数 vs 三位数）。
