## I — 方法论骨架 (Interpretation)

"让特效长在角色身上"不是一个布尔开关，而是**十个独立开关**，填 0 或 1（0 = 不跟随，1 = 跟随）。它们按维度解耦：

```
旋转跟随（含 X/Y/Z 轴）
移动跟随（含 X/Y/Z 轴）
缩放跟随（含 X/Y/Z 轴）
FollowBone —— 特效触发后是否继续跟随父级骨骼
```

**核心决策法：按维度逐轴问"要不要跟"，而不是整体开或整体关。**

三条经验判据：
- **火焰类、需要始终朝上/保持朝向的特效** → 关闭**旋转**跟随（否则会跟着角色翻滚）。
- **需要保持尺寸固定的特效** → 关闭**缩放**跟随。
- **粒子类特效** → `FollowBone` 设 **0**，让粒子生成后脱离骨骼自由运动；设 1 会让粒子被骨骼每帧拽回去，Velocity/Gravity 全被覆盖。

**两个极易踩的反直觉点：**

1. **Position 相关项设为 0 ≠ "关闭跟随"**，而是**特效会跑到关卡的世界原点（坐标零处）**。这与 Rotation/Scale 的语义**不对称**——所以除非你确实想让它落在原点，**不要去动 Position**。这属于最难归因的故障：编辑器不报错，游戏里特效出现在地图某个固定角落。
2. **大小写敏感的骨骼名**：Bone 栏的名字必须与 3DS Max 中**完全一致、区分大小写**，否则绑定**静默失败**——游戏不报错，只是特效不跟随。所以从 3DS Max 复制名字时**用复制粘贴，不要手打**。

**写入骨骼名的固定动作**（与 `efx-safe-structure-edit` 的字节长度同步同源）：
① 把骨骼名字段的 size 改成目标长度（示例改 10）→ ② 按差额插入字节（4 字骨骼名原本已有 2 字节，插 8 字节）→ ③ 按 F5 刷新 → ④ 在 Bone 栏填名。

**一条跨段联动**：`PtLife` 里设 `ukn2 = 3`（让子特效像骨骼一样跟随父特效）时，**只有在 ParentOptions 的 FollowBone = 1 的前提下才生效**。只改一个不会有跟随效果。（该联动的主动作归 `efx-conditional-trigger`，此处仅记录它对 FollowBone 的依赖。）

## A1 — 源素材中的应用 (Past Application)

### 案例 1：十个开关的语义清单与"仅不跟随旋转"对照

- **问题**：想让特效保持朝向、但位置仍贴在角色身上。
- **方法的使用**：示例中十个开关初始全为 1；作者做对照演示，**只关掉"跟随旋转"这一项**（移动、缩放仍跟随）。
- **结论**：各开关彼此**独立**，可以单独关闭某一维度而不影响其他。
- **结果**：验证了"逐轴解耦"的决策法确实可用。

### 案例 2：给无骨骼的特效组链接骨骼

- **问题**：一个特效组原本没绑任何骨骼。
- **方法的使用**：把骨骼名字段 size 改为 10 → 为 4 字骨骼名插入 8 字节（原本已有 2 字节）→ F5 刷新 → 在 Bone 栏填入与 3DS Max 一致、区分大小写的骨骼名。
- **结论**：绑定成功的前提是"size 同步 + 名字精确匹配"两件事都做对。
- **结果**：特效可跟随指定骨骼；作者补充"要绑与其他特效组相同的骨骼还有更简单的方法"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 想让特效**贴在角色的某个骨骼上**（"把手上的火绑到手""跟着武器走"）。
2. 特效**跟着角色一起翻滚/旋转**了，但希望它**保持朝向**。
3. 特效**不跟随**了——明明填了骨骼名却纹丝不动（静默失败）。
4. 特效**跑到地图某个角落**去了，不在角色身上（Position 被清零的典型症状）。
5. **粒子特效贴着角色不散开**，加大 Velocity 也没用。
6. 不确定那十个 0/1 开关各是什么、该怎么配。

### 语言信号（用户的话里出现这些就应激活）

- 中文：「绑定骨骼」「跟随骨骼」「ParentOptions」「FollowBone」「特效不跟随」「跟着翻滚」「保持朝向」「特效跑到地图角落」「粒子不散开」「骨骼名大小写」
- English: "attach to bone", "follow the bone", "ParentOptions", "FollowBone", "effect doesn't follow", "keeps rotating with the character", "effect at world origin", "particles stuck to character", "bone name case sensitive"

### 与相邻能力的区分

- 与 `efx-conditional-trigger` 的区别：本能力管**静态的跟随配置**（常驻的十个开关 + 骨骼名写入）；那个管**触发时机**（何时出现、何时消亡、碰撞触发）。"PtLife ukn2=3 需要 FollowBone=1"这条联动，主动作找那个，本能力只声明依赖。
- 与 `efx-safe-structure-edit` 的区别：本能力的"改骨骼名 size"是字节长度同步的一个实例；若改的是其他结构（增删段/特效组），找那个。
- 与 `efx-attribute-selection` 的区别：本能力回答"跟随怎么配"；"想改别的需求该去哪个段"找那个。

## E — 可执行步骤 (Execution)

1. **按维度列需求，逐轴定 0/1**：
   - 位置要不要跟？（**谨慎**：置 0 会跑到世界原点，一般保持默认）
   - 旋转要不要跟？（要保持朝向 → 0）
   - 缩放要不要跟？（要保持尺寸 → 0）
   - 粒子类？→ FollowBone = 0。
   - 完成标准：写出每个维度的取值和理由。

2. **确认骨骼名与 size**：
   - 确定目标骨骼名（从 3DS Max **复制粘贴**，注意大小写）。
   - 把骨骼名 size 字段改成目标字节数；按差额插入字节（每字符 2 字节，扣除原有）；
   - 完成标准：F5 后变量树无 `*ERROR`，size 与实际字符数一致。
   - 判停条件：若目标骨骼名与现有某个特效组相同 → 优先"从那个特效组复制整段"，比手工写更省事。

3. **在 Bone 栏填入骨骼名并 F5**。
   - 完成标准：变量树显示骨骼名完整、无报错。

4. **进游戏验证跟随行为**。
   - 完成标准：特效贴在正确骨骼上、朝向/尺寸符合预期。
   - 判停条件：若完全不跟随 → 先怀疑**骨骼名大小写不匹配**（静默失败，编辑器无报错）；若特效在关卡固定角落 → 检查 Position 是否被清零。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要配的是"**何时**触发/消亡"而不是"**怎么**跟随" → 用 `efx-conditional-trigger`。
- 改的是"骨头以外"的属性（时长、运动、散布） → 用 `efx-attribute-selection`。
- 编辑器已报错 → 先用 `efx-crash-troubleshoot`。

### 源素材中警告的失败模式

- **把 Position 设为 0** → 特效飞到关卡世界原点（不是"关闭跟随"）。语义与 Rotation/Scale 不对称，是高频误操作。
- **粒子类特效 FollowBone = 1** → 粒子被骨骼每帧拽回，Velocity/Gravity 全失效，贴着角色不散开。
- **骨骼名大小写不一致 / 手打错字** → 静默失败：游戏不报错，特效就是不跟随。最难排查的一类。
- **改了骨骼名却没同步 size** → 后续数据错位。
- **改完不按 F5** → 变量树是旧偏移，后续编辑基于错误结构。

### 作者的盲点 / 局限

- 十个开关与"三轴 × 三变换 + FollowBone"的对应关系，作者**未逐项列全命名**；本能力按语义归纳，具体栏位名以模板变量树为准（见 `efx-file-structure-model`）。
- "粒子类设 0"是作者的经验建议，非引擎规范；反向需求（如粒子要贴住角色）未讨论。
- 只验证 DMC5；骨骼命名规则来自 3DS Max 工作流，**其它 DCC 未覆盖**。

### 容易混淆的邻近方法

- **"跟随配置" vs "触发配置"**：一个是常驻关系（ParentOptions），一个是时机（PtLife/PtColliderAction）。
- **Position 的语义 vs Rotation/Scale 的语义**：前者置 0 = 去原点，后两者置 0 = 不跟随。**不要按同一个直觉处理。**
- **"特效没绑上" vs "绑上了但不跟随"**：前者要查 size/名字是否写入，后者优先怀疑大小写。
