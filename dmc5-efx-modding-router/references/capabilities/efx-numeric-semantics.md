## I — 方法论骨架 (Interpretation)

EFX 里的"数字框"看起来一样，语义却按字段分成好几套。填错不会报错，只会静默地表现出奇怪的结果——或者直接把游戏搞崩。所以改数值前必须先认出**这个字段属于哪一套**。

**第一套：两套随机机制，看后缀分辨**
- 字段名带 `Min`/`Max` → 在 `[Min, Max]` 区间内取随机。
  **硬约束：Max ≥ Min + 1**，否则游戏崩溃（**Min 和 Max 都是 0 时除外**）。
  例：DurationMin=5、DurationMax=10 → 每次在 5~10 间随机。
- 字段名带 `Range` → 以基准值为中心做对称浮动，实际值 = 基准值 ± Range。
  例：ScaleX=10、ScaleXRange=2 → 取 8~12。Speed=1、SpeedRange=0.3 → 取 0.7~1.3。
- 同一个属性里两种可能并存，**不要互相套用**。

**第二套：角度一律是弧度**
所有旋转字段填弧度，不是角度：90° = **1.57079**（π/2），建议精确到小数点后五位。
符号域不对称：**位置和旋转可以填负值**（表示反向），**缩放不能填负值**。

**第三套：加速度的三段判据**（RotateAnim / ScaleAnim 等动画段通用）
- `0 < 加速度 < 1` → 动一会儿就停下来
- `加速度 = 1` → 一直匀速（默认值）
- `加速度 > 1` → 越来越快，直至消失

**第四套：时间单位往往按帧**
Spawn 的延迟/间隔/循环周期填整数，单位疑似帧：**填 60 ≈ 延迟 1 秒**（与游戏帧率相关）。所以"延迟 3 秒"要填约 180。

**第五套：几个反直觉的特殊值**
- Life 的 `Duration = 1`（某个语义未明、教程标注"未知效果"的字段设为 1）→ 效果**一直存在**（无限）。
- Spawn 的**循环周期填 0 → 一直都会出现**（不是"关闭生成"）。
- 某 MAX 值必须 **≥ 1** 特效才能出现。
- TypeGpuBillboard 的亮度单位**可能是 nits**，太低没效果，**建议 ≥ 500**（作者原话"太低了没效果，建议干到 500 以上看看"）。
- Velocity3D：方向或速度填**负值 = 反向发射**；重力填**负值 = 向上飘**。
- EmitterShape3D 的散布类型：**填 1 = 球形，填 2 = 环形**。
- ParentOptions 的十个开关**只能填 0 或 1**（0 = 不跟随，1 = 跟随）。
- `uint32 ukn`：**0 = 只在特定条件下触发，2 = 无限制条件**（注意 2 不是"2 个条件"）。

**第六套：字段名不等于语义**
最典型的反例：用 PtLife 做"父特效消亡时触发子特效"时，触发时机**只认 Life 里的 `Duration`**，而 `FadeOutDuration`（听起来最像"消亡时刻"的那个）**被完全忽略**。所以遇到"改了没反应"，先怀疑字段名误导，而不是继续加码。

## A1 — 源素材中的应用 (Past Application)

### 案例 1：Min/Max 的崩溃边界

- **问题**：在 Life 属性里调特效寿命，用 Min/Max 表示随机范围。
- **方法的使用**：作者提出硬规则——Max 必须比 Min 大 1 以上，否则游戏崩溃；两者都是 0 是唯一例外。
- **结论**：这不是"逻辑限制"，而是**崩溃条件**。所以"想让时长固定为 2 秒"这种需求不能写成 Min=2、Max=2。
- **结果**：这条成为全教程最高频出现的硬约束；起始帧（Starting Frame）同样适用，且**在 TypeMesh 与 UV Sequence 两处都会中招**。

### 案例 2：加速度调转速

- **问题**：想让旋转"转一会儿自己停"。
- **方法的使用**：把加速度填在 0 与 1 之间；想匀速就填 1；想越转越快炸开就填大于 1。
- **结论**：一个字段就覆盖了"衰减 / 匀速 / 加速"三种运动模式，不必找别的字段。
- **结果**：作者用同一个判据同时解释了 RotateAnim 与 ScaleAnim 两个不同的段。

### 案例 3：Spawn 的延迟与周期

- **问题**：想让特效延迟约 3 秒才出现，并按固定间隔循环。
- **方法的使用**：两两间隔填 15、循环周期填 30、延迟填约 180（帧率 60 时约 3 秒）；并确认某 MAX 值 ≥ 1 否则特效根本不出现。
- **结论**：这类字段的单位是帧不是秒，换算依据游戏帧率。
- **结果**：进游戏后观察到与设定相符的生成节奏。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 想给一个字段**填一个具体数值**，但不确定单位（"旋转填 90 吗""延迟 3 秒填多少"）。
2. 需要**随机化**效果（"让每次触发大小略有不同""让速度有浮动"），在 Min/Max 和 Range 之间犹豫。
3. 填完之后**游戏崩了**，怀疑是数值违规（尤其是刚动过 Min/Max）。
4. 想调**运动节奏**（转多久停、缩放怎么衰减）。
5. 遇到"改了没反应"的字段（如 FadeOutDuration），需要判断是不是字段名误导。
6. 碰到一组**语义不明的字段**（ukn / 未知效果），需要知道哪些数字是安全的、哪些不能碰。

### 语言信号（用户的话里出现这些就应激活）

- 中文：「旋转填多少」「90 度怎么填」「Min 和 Max 怎么填」「Range 是什么意思」「改完就崩了」「太大/太小」「为什么改了没反应」「这个是弧度还是角度」「延迟 3 秒填多少」
- English: "what value should I put for rotation", "radians or degrees", "Min and Max range", "the game crashes after I changed a number", "how many seconds is this value"

### 与相邻能力的区分

- 与 `efx-attribute-selection` 的区别：本能力回答"**值填什么**"；那个回答"**改哪个段**"。用户问"该改哪里"找那个，问"填多少/什么单位/为什么崩"找本能力。
- 与 `efx-crash-troubleshoot` 的区别：本能力管**数值域**这一条根因；排错能力负责在崩溃/失效时先分流到"是数值问题还是结构问题"。
- 与 `efx-render-type-selection` 的区别：那个解决"能力边界"（比如 GpuBillboard 不支持逐轴缩放）；本能力解决"数值域边界"。

## E — 可执行步骤 (Execution)

1. **先认后缀，判断属于哪一套**：
   - 带 `Min`/`Max` → 区间随机（强制 Max ≥ Min+1，全 0 除外）
   - 带 `Range` → 基准值 ± 浮动
   - 名字含 Rotation/Angle → 弧度
   - 名字含 Acceleration → 三段判据
   - 名字含 Delay/Interval/Cycle（Spawn 内）→ 帧
   - 完成标准：能说出这个字段属于哪一套，以及它的约束。

2. **算目标值**：
   - 弧度 = 角度 × π / 180（90° → 1.57079），保留五位小数。
   - 帧 = 秒 × 帧率（60fps 时 3 秒 ≈ 180）。
   - 随机 → 决定用 Min/Max（区间）还是 Range（对称浮动）。
   - 完成标准：写出具体数字，并注明它是"区间端点"还是"浮动量"。

3. **自查安全边界**：
   - 任何 Min/Max：Max ≥ Min+1？两者是否都是 0？（是则安全）
   - 缩放：是否填了负值？（不允许）
   - ParentOptions：是否只填了 0/1？
   - GpuBillboard 亮度：是否 ≥ 500？
   - ukn：0 还是 2？是否明白自己选了哪一档？
   - 完成标准：每一项都通过，或明确记录"这一项我不确定"。
   - 判停条件：若字段名含 `ukn` 或标注"不明/未知" → 不要盲改，见 B 段。

4. **改完 F5 重解析并进游戏验证**。
   - 完成标准：效果符合预期，游戏不崩。
   - 判停条件：若结果与预期相反（例如"改了更慢"而不是更快），回到步骤 1 重新确认字段属于哪一套，**尤其警惕字段名误导**（参考 FadeOutDuration）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 需要先决定"改哪个属性"时 → 用 `efx-attribute-selection`。
- 崩了但不确定是不是数值问题 → 先用 `efx-crash-troubleshoot` 分流。
- 面对的是 `ukn` / 标注"不明"的字段 → 本能力**故意不提供取值建议**，因为作者本人也没测出来。

### 源素材中警告的失败模式

- **Min/Max 区间为空**（Max ≤ Min）→ 游戏崩溃；唯一安全例外是两者都为 0。
- **把 Min/Max 当 clamp**：它不是"把值限制在区间内"，而是"每次触发在区间内随机取"。
- **旋转填度数**（填 90 而不是 1.57079）→ 实际是 90 弧度（约 5157°），结果荒谬。
- **给缩放填负值**（想镜像）→ 不被支持。
- **把"循环周期 0"理解成"关闭"** → 语义完全反了（0 = 一直出现）。
- **用 FadeOutDuration 去调消亡触发时机** → 完全无效，触发只认 Duration。
- **按百分比填 GpuBillboard 亮度**（如填 1）→ 什么都看不见。
- **把 ukn = 2 理解成"2 个条件"** → 实际是"无限制条件"。

### 作者的盲点 / 局限

- 大量数字的语义是**作者自己标注"未确定/不明"**的：Spawn 的完整机制、Velocity 的 ukn 系列、EmitterShape3D 里那 12 个值（"我测了好久发现好像只有编号 0 有影响"）、PtCollision 的 ukn8~11。这些只能当"作者的经验观察"，不能当规格。
- **单位多有"可能"字样**：nits 是作者的推测；Spawn 延迟"单位可能是帧""可能跟你游戏帧率有关"。填值时请留出试错余量。
- 作者只验证了 DMC5 这一版引擎的取值域。

### 容易混淆的邻近方法

- **Min/Max vs Range**：本领域最常混的一对。判据是后缀：`XxxMin/XxxMax` 是两端点；`XxxRange` 是浮动量。
- **"值域非法" vs "结构不一致"**：前者立刻崩溃（通道 B），后者在编辑器里就报 `*ERROR`（通道 A）。看到编辑器干净却崩溃，优先想数值。
- **"字段名" vs "字段语义"**：FadeOutDuration 是最标准的反例。
