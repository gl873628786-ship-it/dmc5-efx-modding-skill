# 安全增删 EFX 结构（计数与字节长度同步）

## R — 原文 (Reading)

> 删除代码之后记得更改 effect（count）。
> 选定：4 个字节（范围：24[18h] 到 27[1Bh]）
> `*ERROR Line 2432：模板读取超出文件末尾`

— 视频分 P 02《增加、减少特效组》[01:12]–[01:21]（画面文字 OCR）

> 复制、粘贴，然后 Override Hash Count 加 1……每次改变嵌入 efx 体积时都必须执行 —— 这也是作者推荐用 Linked 的原因。

## I — 方法论骨架 (Interpretation)

EFX 文件的每一次结构增删，都必须收敛到同一个四拍动作，缺一拍就废：

**① 复制**：从别处选中一段**完整的**结构（一个 Effect，或一个 Segment），Ctrl+Shift+C。
**② 定位与粘贴**：先把光标点到目标位置（**这一步不能省**，否则会覆盖编辑器里残留的蓝色高亮选区），再 Ctrl+Shift+V；要插到中间时改用「插入字节」而不是覆盖式粘贴。
**③ 同步数字**：回头把对应的 **count** 或 **size** 加减 1 / 加减差额字节。
**④ 重解析**：按 F5 让模板重新解析文件，确认变量树里没有 `*ERROR`。

第 ③ 步是这个方法论真正的内核，因为它有**三个彼此独立的层级**，极易漏：

- **计数层**（整数）：`Effect Count`（文件头，管有几个特效组）、`Segment Count`（**每个 Effect 各自一份**，管这个特效组里有几个属性段）、`Linked EFX Count`、`Override Hash Count`（TypeMesh 专属）、条件组的个数。
- **字节长度层**（以字节为单位，不是字符）：`Path/EFX size`（内嵌 efx 体积）、`pathsize`（资源路径长度，**每 1 个字符 = 2 字节**）、骨骼名的 size、Condition Block 的 size。
- **排序层**：新增 Segment 后按 Id 升序摆放。

判断该动哪一层的方法很直接：**问自己"我改的是个数，还是长度？"** 增删整套结构 → 动计数；只把某个字符串改长改短 → 动长度；两者都别忘。

## A1 — 源素材中的应用 (Past Application)

### 案例 1：删除幻影剑的一部分特效组

- **问题**：想知道特效组是不是真的对应游戏里的可见效果。
- **方法的使用**：在 p02 里选中幻影剑相关的一段结构（约 6132 字节），按 delete 删除，文件从 12,378 字节变成 6,246 字节。
- **结论**：删掉结构后**必须回头把 Effect Count 减 1**，否则模板立刻报 `*ERROR Line 2432: 模板读取超出文件末尾`。
- **结果**：补上计数后进游戏，幻影剑特效"很明显地少了很多"，验证结构与视觉效果的对应关系成立。

### 案例 2：给基础纹理特效添加 ScaleAnim 属性（一个与文件头无关的计数）

- **问题**：基础纹理特效只有 6 个属性，想加一个缩放动画。
- **方法的使用**：从别的特效组复制 ScaleAnim 段，粘到 Life 段之前（按 Id 升序：2Ah 在 2Ch 前）。
- **结论**：粘贴后报 **`*ERROR Line 153`**（注意行号只有三位数，远小于案例 1 的 2432）——因为它漏掉的是**该 Effect 局部的 Segment Count**，而不是文件头的 Effect Count。
- **结果**：这一步同时暴露了"报错行号的量级 = 错误所在的层级"这条推理线索。

### 案例 3：加长资源路径

- **问题**：想把 uvs 路径从 53 个字符改到 55 个。
- **方法的使用**：**先**把 `pathsize` 改成 55，**再**在路径字段后插入 (55−53)×2 = 4 个字节，然后按 F5 重解析。
- **结论**：顺序不能反——先算"改了多长"，再补"多长"的字节。
- **结果**：路径与长度重新对齐，模板恢复正常解析。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill？

1. 想给一个现成特效**加一个属性**（加发光、加缩放动画、加扭曲）——"我想让它也转起来/也变大"。
2. 想**删掉**某个特效组或某个属性段，做减法版特效。
3. 想**复制**别的特效里的某个段为己用（从别的 efx 里"抄"一段）。
4. 想**改资源路径**（把贴图/模型指到自己的文件），长度发生变化。
5. 改完之后 010 Editor 报错，或游戏崩了，需要确认是不是漏同步了某个数字。

### 语言信号（用户的话里出现这些就应激活）

- 中文：「怎么给这个特效加一个属性」「删掉这个特效组」「复制一段过来」「路径改了不生效」「count 要改吗」「我加了属性就报错了」
- English: "add a segment to this efx", "how do I remove an effect group", "copy an attribute from another efx", "do I need to update the count", "template read past end of file"

### 与相邻能力的区分

- 与 `efx-crash-troubleshoot` 的区别：本能力是**动手增删时同步数字**（预防 + 修正动作）；`efx-crash-troubleshoot` 是**已经报错/已经崩了之后反推根因**（诊断路径）。用户说"我要加一个属性"找本能力，说"我改完崩了/报错了"找那个。
- 与 `efx-attribute-selection` 的区别：那个回答"该改哪个段"（选型），本能力回答"选定之后怎么改才不出错"（执行）。
- 与 `efx-edit-hygiene` 的区别：那个是跨全部编辑动作的前置纪律（备份、路径无中文、不盲改 ukn）；本能力是增删这个具体动作的同步清单。

## E — 可执行步骤 (Execution)

1. **先备份**：把目标 efx 复制一份到游戏目录之外（`natives` 是 MOD 挂载层，卸载 MOD 会被整个删除）。
   - 完成标准：游戏目录之外存在一份同名副本。

2. **确认你要动的是哪一层**：个数（Effect/Segment/Linked EFX/Override Hash/Condition）还是长度（pathsize / EFX size / 骨骼名 size）。
   - 完成标准：能用一句话说出"我要动的是 X 的 Y 计数/长度"。
   - 判停条件：若只是改一个数值（如把缩放的 1 改成 2），**不需要**动任何计数，直接跳到步骤 6。

3. **复制源结构**：在变量树里选中一个**完整的** Effect 或 Segment（选中后编辑器会显示它的字节范围与大小），Ctrl+Shift+C。
   - 完成标准：剪贴板里有一份完整结构，编辑器显示了它的字节区间。

4. **定位后粘贴**：
   - 要追加到末尾 → 把光标点到最后一个同类结构之后，Ctrl+Shift+V。
   - 要插到中间 → **先点一下目标位置取消旧选区**（否则会覆盖蓝色高亮部分），再用「插入字节」（Ctrl+Shift+I）的方式插入。
   - 带限制条件（ukn=0）的 efx → **一律粘到末尾**，不要插中间，否则条件表的索引会整体平移。
   - 完成标准：文件大小按"源结构字节数"增加。

5. **同步数字（关键步）**：
   - 新增 Effect → `Effect Count` +1；删除 → −1。
   - 新增 Segment → **该 Effect 内部的** `Segment Count` +1。
   - 新增 Linked/Embedded EFX → `Linked EFX Count` +1；若用的是 Embedded，还要把 `Path/EFX size` 加上新增字节数。
   - 新增 Override → `Override Hash Count` +1。
   - 路径变长 → `pathsize` 先改，再插 (新增字符数 × 2) 个字节。
   - 骨骼名改名 → 先把其 size 改成目标长度，再插差额字节。
   - 新增条件 → 条件组个数 +1，并核对 Condition Block 的 size。
   - 完成标准：所有相关计数/长度与实际内容一致。

6. **按 F5 重解析**：让模板用新结构重新解析文件。
   - 完成标准：变量树里**没有 `*ERROR`**；若出现 `*ERROR Line xxxx：模板读取超出文件末尾`，说明还有一处声明长度 > 实际长度，回到步骤 5 逐项核对；行号是四位数（如 2432）优先怀疑文件头计数，是三位数（如 153）优先怀疑该 Effect 的 Segment Count。

7. **进游戏验证**：保存 → 重进关卡 → 观察。
   - 完成标准：改动的效果在游戏内可见；若不可见，转 `efx-crash-troubleshoot`。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 只改**字段数值**（把旋转改成 1.57079、把 Duration 改成 5）时——这不动任何计数，用不上本能力（转 `efx-numeric-semantics`）。
- 面对**模板没有解析出来的结构**时——本能力的"复制—粘贴"依赖变量树能显示该结构；模板未覆盖的区域无法用这套动作安全增删。
- 换的是**另一个 RE Engine 游戏**（RE2/RE3/RE4/MHR）的 efx——属性表与计数布局不同，本能力的同步目标可能不存在或位置不同。

### 源素材中警告的失败模式

- **忘同步 Effect Count / Segment Count** → `*ERROR Line xxxx：模板读取超出文件末尾`（本领域最高频崩溃）。
- **粘贴前没有重新定位** → 直接覆盖蓝色高亮选区，静默损坏数据，往往到进游戏才发现。
- **把段插到中间**（尤其带限制条件的 efx）→ 索引平移，触发关系全乱。
- **Embedded EFX 改体积后忘同步 Path/EFX size** → 外层解析错位（所以作者推荐一律用 Linked）。
- **pathsize 只改字符串不改声明、或插入字节数不等于"新增字符数 × 2"** → 后续字段整体错位。
- **骨骼名 size 未同步，或名字与 3DS Max 中大小写不一致** → 绑定静默失败（游戏不报错，特效只是不跟随）。

### 作者的盲点 / 局限

- 作者的建议"添加属性后按 Id 升序排列"，与他自己"属性排序有无影响暂且不明"的说法（p04 [00:26]）**互相矛盾**。本能力把它当**纪律**（低成本、无害）而非**定律**：不必因为"排序没用"就不排，也不要断言排序会改变行为。
- 整套动作是**经验归纳**（"否则游戏崩溃（原因未知）"），没有引擎层面的解释，因此不可外推到模板未覆盖的新结构。遇到没见过的情况，只能试错。

### 容易混淆的邻近方法

- **"计数"与"长度"混为一谈**：Effect Count 是整数个数；Path/EFX size 是字节长度。二者都叫"要同步的东西"，但算法不同（±1 vs ±字节数）。
- **Effect Count 与 Segment Count 混为一谈**：前者在文件头、管特效组个数；后者**在每个 Effect 内部**、管该组的属性段个数。报错行号量级是区分它们的最快线索。
